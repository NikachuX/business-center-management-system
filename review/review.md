## Замечания к работе одногруппника

### 1. Даты бронирования

- Файл: `src/java/Booking.java`.
- Место: метод `bookObject()`, строка 41.
- Ссылка на комментарий: https://github.com/Dimasik2007123/educational-practice-scripts/commit/aae0f4a689a569a8e6254169c5e237fa4f6ae03b#commitcomment-211169151

```java
String reason = data.availability(object, bookingDate, expirationDate, null);
```

При проверке удалось сохранить бронь с началом 13.10.2026 и окончанием 12.10.2026, если создать её через открытый конструктор и вызвать bookObject(). Объект при этом получил статус «забронирован». В Python дата окончания рассчитывается от даты начала, поэтому такой интервал не возникает. Предлагаю в bookObject() проверять порядок дат перед проверкой доступности.

### 2. Акт приёма-передачи с датой до сделки

- Файл: `src/java/SaleItem.java`.
- Место: метод `registerCertificate()`, строка 29.
- Ссылка на комментарий: https://github.com/Dimasik2007123/educational-practice-scripts/commit/aae0f4a689a569a8e6254169c5e237fa4f6ae03b#commitcomment-211169193

```java
data.certificates().add(cert); return cert;
```

При проверке удалось зарегистрировать акт от 12.10.2026 для сделки от 13.10.2026. Выдача ключей по такому акту отклоняется, а зарегистрировать акт с правильной датой уже нельзя: для этой позиции акт числится созданным. Предлагаю проверять дату акта относительно даты сделки перед сохранением.

### 3. Истёкшая бронь скрывает объект из поиска

- Файл: `src/java/RealEstateObject.java`.
- Место: метод `matches()`, строка 67.
- Ссылка на комментарий: https://github.com/Dimasik2007123/educational-practice-scripts/commit/aae0f4a689a569a8e6254169c5e237fa4f6ae03b#commitcomment-211169730

```java
&& equal(criteria, "real_estate_status_id", realEstateStatusId)
```

На исходных данных бронь объекта № 3 закончилась 15.09.2026. При поиске свободных объектов на 13.10.2026 он не попал в результаты: у него остался статус «забронирован». При этом на ту же дату программа успешно создала для него новую бронь. Предлагаю при поиске свободных объектов учитывать запрашиваемые даты и использовать ту же проверку доступности, что и при бронировании.
